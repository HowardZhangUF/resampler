# Resampling triggers on the filtering benchmark

Same harness, data, seeds and resamplers as the published runs; only the rule that decides *when* to resample changes. 50 steps; 100 filter runs over 10 observation sequences (10 runs for OT and Gumbel, which stop at N=128). CIs cluster by observation sequence.

| Trigger | Rule |
|---|---|
| `ess` | E_2 = 1/sum w^2 < 0.5 N |
| `cv2` | CV^2 = mean((N w - 1)^2) > 1 |
| `entropy` | E_H = exp(-sum w log w) < 0.5 N |
| `maxweight` | E_inf = 1/max w < 0.5 N |

`cv2` is not run separately: CV^2 = N/E_2 - 1, so CV^2 > 1 is exactly E_2 < N/2 (checked trial by trial against stored results). Since E_inf <= E_2 <= E_H, at the same 0.5N threshold `maxweight` resamples most often and `entropy` least often. `dsr_noclip` is omitted: the clamp acts only on gradients, so its filter trials equal `dsr`.

`*_matched` triggers use per-model thresholds tau (resample when score < tau N), calibrated by bisection so that particles/systematic resamples as often as under `ess` (N=[128, 512], 30 seeds each). Rates are resampling steps out of 50:
